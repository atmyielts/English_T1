# Simulator saving and recovery

IELTS, SAT, TOEFL and iTEP previously ignored failed answer writes and could advance a section or complete an attempt anyway. Answer writes now run in order, the final snapshot waits for earlier writes, and a failed final save keeps the section open with an explicit retry. A synchronous answer reference preserves the latest edit even when the learner submits immediately. Submission and save retries prevent duplicate in-flight actions and freeze question editing until the write settles. Changing back to an earlier saved answer no longer lets a pending older choice overwrite it.

Unconfirmed edits are kept in bounded sessionStorage for the same app, learner, attempt and section. This is a per-tab recovery draft, not proof of a server save. Owned server state is loaded first; reload offers an explicit restore/discard decision, warns when server answers changed, and removes only matching acknowledged drafts. Unrelated question IDs, malformed/expired records and reserved properties are rejected. The draft expires after24 hours and is limited to200 questions/512K serialized characters. Denied or full storage leaves edits in memory and explains the reload limitation. Acknowledged answers are removed from the draft; an older acknowledgement cannot erase a newer edit.

Completion and abandonment now require a returned session ID and its expected status. An HTTP success with no matching row cannot silently claim the attempt was closed. Failed closing commands retain the current screen. Abandonment first attempts to save the final answers and reports failures.

Exam deadlines remain enforced by the existing server policy. After expiry, question edits are locked. If a timed final save fails, the learner can keep/copy the visible unsaved work or explicitly continue with only server-confirmed answers. That action makes a fresh authenticated owned-state read, requires the same attempt/section, and sends no late answer writes. Unsaved work is explicitly excluded from scoring; the screen never promises that a rejected post-deadline draft was stored.

Local validation includes15 shared save/draft tests, four isolated production builds and 44 actual player-route browser fault checks (11 per simulator) with synthetic owned state and all external requests blocked. Coverage includes failed saves, reload, write ordering, server conflicts, returned-error/empty completion replies, expired editing, explicit saved-answer continuation, storage denial and320/390/1280 widths. The new recovery panel is checked with scoped WCAG2A/AA rules. Evidence identifies mocked checks; it does not claim real paid attempts, grading calls or provider delivery.
