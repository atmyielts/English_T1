# SAT drill start integrity

A lost start response can currently create a second drill on retry. The service also loads live questions and keys for an unsubmitted attempt, so a content revision can change the work a learner started. This backend release creates the shared session, attempt and private frozen question set in one transaction, keyed by an authenticated actor and request UUID. Identical retries replay that original drill. Changed filters conflict; another actor receives a private not-found response. No-match or failed starts leave no orphan session.

Owned resume and first submission use the frozen questions and keys. A source outage or corruption is explicit and does not substitute newer content. The existing atomic completion body remains behind a snapshot validation wrapper; its original receipt, aggregate updates and retry protections are preserved. Legacy attempts created by version17 have no start snapshot and remain compatible. The whole `correct` property is removed before scoring. Browser roles cannot access the private source table or execute either command; service permissions override default grants, and snapshots cannot be updated.

This PR changes no frontend behavior, Tutor implementation, content, prices, provider budgets or workflow files. The separately prepared UI retains start IDs across a lost response/reload until Lab loads and adds Reviews/Notebook/Today recovery. That frontend will be released after this server change is verified. Old clients still work, but they cannot replay an unknown start identity until upgraded. Existing question rows must be retired without physical deletion; this release does not qualify deleting content rows or repairing legacy partial progress.
