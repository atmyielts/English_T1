# Candidate account boundary

The published candidate-entry function (version 44) minted Auth credentials from supplied profile details. Its claimed-code recovery also minted the original claimant's credentials without requiring that claimant's authentication. The repaired handler requires a verified, confirmed-email Auth account before any exam lookup and never creates users, generates links, verifies OTPs or returns Auth credentials. Claims and retries are bound to the authenticated account; foreign assigned vouchers and contacts cannot change account ownership.

The Platform sends the current account's bearer token, rejects email or in-flight account changes and discards credentials returned by the older function during the one-deploy boundary. Candidate, voucher and center entry preserve the code through sign-in and reset roster data on account changes. Verified account email is read-only. The four exam root origins are allowlisted before claiming; handoff uses the fragment accepted by current simulator handoffs, keeping credentials out of HTTP query strings. Credentials still exist in the fragment during navigation; replacing this with a scoped handoff is separate work.

Local evidence: 23 Deno handler/client admission tests and Edge typecheck pass; Platform production-configured build passes; 16 Playwright CLI synthetic-provider checks pass for three guest return paths, no guest mutation, read-only email, account-switch isolation, local-session retention, four fragment destinations, bearer header, in-flight switch rejection and mobile navigation/overflow. The CLI script and rendered desktop/mobile screenshots are retained in the owned ignored `supabase/.temp/candidate-auth/` directory. These are local checks, not signed-in hosted customer proof.

Production source was freshly downloaded and its normalized fingerprint matched the unchanged main source. `release/candidate-published-baseline.json` records function version, gateway flag and hash. A read-only public product inventory confirmed the existing IELTS, SAT and TOEFL exam origins use root URLs. iTEP is allowlisted but was absent from that public product inventory.

Release order: normal feature PR, exact-head CI, tracked Pages deployment, then the candidate-entry function only. Before manual deployment, refresh the function version, gateway flag and downloaded source; refuse any drift from the baseline. Prepare an isolated function directory containing only reviewed `index.ts`, `auth.ts`, `handler.ts` and an explicit `verify_jwt=false` configuration. Typecheck the prepared entry point. Download the installed function afterward and compare all three runtime source hashes. Verify unauthenticated rejection and owned QA new entry, retry and foreign-account rejection. No migrations, secret changes or other Edge Functions belong to this release.

The existing multi-table profile/token/session/registration/voucher writes remain non-atomic. This repair does not qualify payment or exam transaction readiness. Atomic mock admission, subscription/seat recovery, signed Click callbacks, source-preserving payment installs and their hosted canaries remain in the separate payment release. Whole-service customer readiness is still unproven.
